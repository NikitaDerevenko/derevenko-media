# Сайт Nikita Derevenko

> **Хостинг:** сайт собирается в статичные файлы (`out/`) и публикуется на GitHub Pages автоматически при каждом push в `main`. Своего сервера нет; заявки принимает функция в Яндекс Облаке (`cloud/lead`).

Двуязычный сайт (RU `/ru`, EN `/en`) Никиты Деревенко — самозанятого специалиста: реклама, сайты и Telegram-сервисы.
Next.js 16 (App Router), React 19, Tailwind CSS, TypeScript. Заявки — в Telegram, аналитика — Яндекс Метрика после согласия на cookie.
Рынок определяется языком: `/ru` — цены в рублях, `/en` — в долларах.

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить переменные
npm run dev                  # http://localhost:3000/ru
npm run build                # статичная сборка в out/ — её и публикует GitHub Pages
npx serve out                # посмотреть сборку локально
npx tsc --noEmit             # проверка типов
```

`npm run build` делает три шага:

1. `prebuild` — `scripts/make-og.mjs` рисует картинки для соцсетей 1200×630 в `public/og/` (главная RU/EN и каждая страница направления) из текстов словарей.
2. `next build` — собирает статичный сайт в `out/`; **падает с понятной ошибкой, если не задан `NEXT_PUBLIC_SITE_URL`** (или в нём шаблонный домен).
3. `postbuild` — `scripts/check-build.js` проверяет, что в `out/` не осталось шаблонного домена.

Переменные окружения сайта (не секреты, лежат в `.env.production`):

| Переменная | Что это |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта (`https://ваш-домен.ru`). Обязателен для сборки: от него строятся canonical, hreflang, sitemap, robots, Open Graph, JSON-LD |
| `NEXT_PUBLIC_LEAD_URL` | Адрес функции приёма заявок в Яндекс Облаке. Пусто — формы показывают ошибку и предлагают написать в Telegram |
| `NEXT_PUBLIC_YM_ID` | Номер счётчика Яндекс Метрики. Пусто — Метрика не подключается |

Токен бота, id чата, бакет для копий заявок и лимит заявок задаются **только в переменных функции** в Яндекс Облаке — см. `cloud/lead/README.md`. Защита от спама: скрытое поле-ловушка, отправка быстрее 2 секунд отсекается, лимит по IP, заявки принимаются только с адреса сайта.

## Что заполнить

Плейсхолдеры `{{...}}` в `lib/site.ts`. Пока значение не заменено, блок скрыт, а цена показывается как «по запросу».

1. **`LUMOS_PROOF`** — строка «×4» по концертам в Благовещенске: период, расход, выручка, покупки, способ атрибуции, дата среза. Строка появится, когда заполнены все шесть.
2. **`/public/projects/ads-lumos/proof.webp`** — скриншот-подтверждение (кабинет/Метрика). Нет файла — блока нет.
3. **`PHOTO_CASE_RESULTS`** — «Итог работы» для `maps-cafe-1` и `maps-cafe-2`: сколько фото/позиций, что опубликовано, срок.
4. **Цены в долларах** (`SERVICES.intl`): поддержка сайта, «форма → таблица → Telegram», бот с оплатой/CRM, поддержка бота.
5. **Фото** — `public/about/photo.jpg` и аватар `public/about/avatar.jpg` (уже добавлены из `Медиа/Фото — портрет в пиджаке.png`). Без файла вместо фото — плашка с инициалами.
6. **Видео** — `public/about/intro.mp4`. Нет файла — блок не выводится.
7. **Email / телефон** — `SITE.email`, `SITE.phone`. Пусто — не выводится.
8. **Демо-боты** — `DEMO_BOTS` (username без @). Пусто — блок не выводится.

После правки текстов первого экрана или направлений картинки для соцсетей пересоберутся при следующем `npm run build` (или вручную: `node scripts/make-og.mjs`).

## Кейсы

Порядок на главной: реальные кейсы — `HOME_CASES`, готовые решения — `HOME_SOLUTIONS` в `lib/projects.ts`. Исходники картинок лежат в папке `Медиа/`, на сайте — WebP в `public/projects/<slug>/`.

- **Кейсы** — работы для реальных клиентов. Цифры — только из кабинетов и аналитики, с источником и периодом.
- **Готовые решения** (`isSolution: true`, `niche`) — разработки для типовых задач ниш. Выводятся отдельным разделом, без плашек; оговорка, что названия заведений в них условные, — в «Условиях работы». Не переносите их в кейсы: выдавать решение за работу для клиента — недостоверная реклама.
- `directions` — на каких страницах направлений показывать работу (по умолчанию — по категории).
- `coverLocales: ['ru']` — обложка с русским текстом показывается только в RU; `coverCaption` — подпись под обложкой.
- `caption` у картинки галереи — подпись под ней.

Логотип — вектор в `components/logo-paths.ts` (обводка `Медиа/Логотип DEREVENKO с фиолетовой деталью.png`): буквы берут цвет текста, деталь в K — акцентный.

## Юридическое

- Реквизиты (ФИО, ИНН, ссылка на проверку статуса в ФНС) — `LEGAL` в `lib/site.ts`; выводятся в подвале, политике, согласии и условиях.
- В каждой форме — отдельная обязательная отметка согласия на обработку ПД со ссылкой на документ согласия и политику. Сервер не принимает заявку без неё (422) и пишет факт согласия со временем в заявку.
- Метрика — только после «Принять» в баннере cookie.
- После правок документов обновите дату `LEGAL.updated`.

Результаты из Яндекс Бизнеса: Статистика → месяц до и месяц после изменений → звонки, маршруты, переходы. Добавьте в `results` кейса с `resultsSource` и `resultsPeriod`. Пишите только то, что видно в статистике.

## Правила контента

- Цифры результатов — только реальные, с периодом и источником.
- Концепты — с плашкой «Концепт», образцы отчётов — «Образец · демо-данные».
- Цены, сроки и состав услуг — только в `lib/site.ts` и словарях, не в компонентах.
- Не обещаем результат — обещаем процесс, сроки и прозрачность.
